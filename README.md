# Django Blog with AI-Assisted Content

A Python/Django blog application with built-in AI content generation and editing, powered by the OpenAI API. Write posts by hand, generate full drafts from a topic, or ask AI to refine existing content — all reviewed as drafts before publishing.

## Features

- **Post management** — create, edit, and delete blog posts with title, excerpt, body, status (draft/published), and tags
- **Tagging** — many-to-many `Tag` model, selectable via checkboxes when writing a post
- **AI post generation** — provide a topic and tone, and get a full draft (title, excerpt, and body) generated by OpenAI, pre-filled into the normal post form for review
- **AI content refinement** — on any existing post, give a free-text instruction (e.g. "make this more concise") and get a revised body suggestion, again for review before saving
- **Author-only permissions** — only the original author can edit or delete their own posts
- **Draft-first workflow** — AI-generated or AI-refined content is never saved directly; it always flows through the normal save form for human review
- **Bootstrap 5 UI** — clean, responsive templates with no custom CSS

## Tech Stack

- **Backend**: Python, Django
- **Database**: PostgreSQL
- **AI Provider**: OpenAI API (`gpt-4o-mini` by default)
- **Frontend**: Django Templates + Bootstrap 5 (via CDN)

## Setup

### 1. Install dependencies

```bash
pip install django openai python-dotenv
```

### 2. Environment variables

Create a `.env` file in the project root (same level as `manage.py`):

```
OPENAI_API_KEY=your-openai-api-key-here
```

Make sure `settings.py` (or wherever your env vars are loaded) calls `load_dotenv()`.

### 3. Run migrations

```bash
python manage.py makemigrations
python manage.py migrate
```

### 4. Create a superuser (optional, for admin access)

```bash
python manage.py createsuperuser
```

### 5. Run the development server

```bash
python manage.py runserver
```

## AI Integration Overview

- **`ai_service.py`** wraps all calls to the OpenAI API behind two functions:
  - `generate_post(topic, tone)` → returns `{"title": ..., "excerpt": ..., "body": ...}`
  - `edit_post_content(existing_body, instruction)` → returns a revised body string
- Both raise a custom `AIServiceError` on failure, which views catch and surface as a friendly message rather than a crash.
- **Generation flow**: user submits a topic on `/posts/generate/` → AI output is stashed in the session → user is redirected to the normal "Add Post" form, pre-filled with the draft → nothing saves until the user reviews and submits normally.
- **Refinement flow**: on the edit page, a separate "Refine with AI" form posts an instruction back to the same edit view → the AI's suggested revision is loaded into the form for review → the user must still click "Update Post" to save it.

## Key URLs

| Path | View | Purpose |
|---|---|---|
| `/` | `home_page` | Landing page |
| `/posts` | `all_posts` | List all posts |
| `/posts/<slug>/` | `view_post` | Post detail |
| `/posts/add-post/` | `add_post` | Create a post |
| `/posts/generate/` | `generate_post_draft` | Generate a draft with AI |
| `/posts/edit/<slug>` | `edit_post` | Edit a post (also handles AI refine) |
| `/posts/<slug>/delete/` | `delete_post` | Delete a post (confirmation required) |

## Notes / Gotchas

- URL patterns with fixed segments (e.g. `posts/generate/`) must be listed **above** the generic `posts/<slug>/` pattern, or Django will incorrectly match the fixed path as a slug lookup.
- `SlugField` defaults to `max_length=50` — AI-generated titles can exceed this, so either truncate generated slugs or increase the field's `max_length`.
- `form.save_m2m()` must be called after `post.save()` whenever `form.save(commit=False)` is used on a form with a many-to-many field (like `tags`), or selected tags will silently fail to save.
